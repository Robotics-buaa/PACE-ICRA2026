# 直接带球测试：站立控制 + 原击球模型右臂

这是用户要求的直接击球/平衡诊断，替代尚未实施的慢速单关节往复测试。
不重跑已完成的站立、上肢保持或扰动检查，不启动任何训练。

## 一次运行

在已打开的 Docker 终端，粘贴执行本地交付文件
`H1_2_hitting_balance_v1_write_and_run_command.txt` 的全部内容。
它核对既有文件和模型，**只新增**远程
`/workspace/projects/PACE-ICRA2026/tools/h1_2/hitting_balance_v1/`，
随后打开原生 Isaac Sim 窗口，默认沿用 DISPLAY，否则用 :1。
单环境、首次回合最多20秒；若提前失稳，停止收集，不拼接复位后的站立片段。
窗口按近实时推进，结束后关闭。一次运行即可，不用额外重跑 headless。

若当前会话没有显示服务，使用 `H1_2_hitting_balance_v1_headless_command.txt`
替代上述文件；两者选一。都不是安装/重建环境。

## 实际控制方式

- 原站立模型 `2026-10-16_13-07-50_805816Z_stand_v1_512x500_seed42/model_499.pt`
  控制双腿12、躯干1、左臂7，共20通道，持续根据当前状态反馈；不是固定腿部角度。
- 原单侧击球模型
  `2026-10-15_03-34-22_h1_2_pred_4096_full/model_9999.pt`
  提供右臂7通道动作，保留其已保存 predictor。
- 前5秒右臂默认目标，5～5.5秒余弦过渡，之后完全使用击球模型右臂输出。
  球从开始就遵循原评估发球机制，不是把球人为贴到球拍上。
- 两个模型分别使用各自的观测语义和 normalizer。原TT495维观测每个99维历史帧
  独立转换成站立模型的球字段/固定准备目标；保留各帧自身朝向和动作历史。
  每步以真实身体位置独立校验转换后的最新准备目标，错误即停止。
- 站位仍为(-1.8,0)，站立模型维持身体锚点，**没有恢复大范围身体追球**。
  原评估发球中不可达的球可能漏接；这次结果不是全分布击球率。
- 继承站立任务的目标硬限位投影、20秒结束和高度/倾斜/漂移失败规则。
  原PD、力矩限制、资产、重力、自由基座和模型权重不变。
  无噪声/延迟/随机推力/质量材料随机化。奖励只被计算，不进行学习。

这是**尚未联合训练的新控制组合**。两个原模型分别训练过，拼接后不保证平衡
或击中；失败也是有用的诊断，不能表述成原站立模型已经具备击球技能。

## 接触与判定

使用 PhysX 独立的“球拍刚体→球刚体”过滤接触视图，读取法向接触力。
每个物理子步读取一次，避免仅50Hz控制帧漏掉短暂碰撞；阈值0.01N。
接口依据 [IsaacLab v2.1 ContactSensor实现](https://github.com/isaac-sim/IsaacLab/blob/v2.1.0/source/isaaclab/isaaclab/sensors/contact_sensor/contact_sensor.py)，
其 `filter_patterns` / `get_contact_force_matrix` 路径；此处直接查询相同后端视图。
若路径或 contact reporter 不匹配会明确报错，不用距离奖励代替接触证据。
球拍刚体接触包含其碰撞几何，不等于拍面中心命中、过网或有效回球。

只对完全启用右臂击球输出后的接触，从随后首个控制帧起做完整2秒身体支撑检查：高度参考±8cm、
倾斜≤0.15rad、锚点漂移≤10cm、双脚Fz>5N比例≥90%、估算负载峰值≤1.2。
这是局部工程筛查，不能替代恢复/完整技能验收；挥拍期间不强行套用安静速度门槛。
完整回合还报告既有站立验收（包括估算接近力矩限制的持续比例）。

- `NO_ACTIVE_PHYSICAL_CONTACT_OBSERVED`：未记录到主动阶段球拍—球接触；
  只能判断恢复右臂动作后的平衡，触球承受能力未验证。
- `POST_CONTACT_WINDOW_INCOMPLETE`：有接触，但至少一个后续2秒窗口未完整记录。
- `CONTACT_WITH_BALANCE_SCREEN_PASS`：有接触、所有后续窗口及完整站立筛查通过；
  仍不是有效回球/正式命中率验收。
- `BALANCE_SCREEN_FAILED`：有接触，但完整窗口的支撑筛查或整段站立未通过。
  若同时存在缺失窗口，报告会保留窗口明细，不将缺失当作成功。

贴回 `[HIT-BALANCE] RESULT`、`BODY`、`CONTACT_WINDOWS` 和报告路径，或完整报错。
原始控制帧、物理子步接触记录保存在原站立运行下新的独立目录。

## 后续训练方向

稳定状态依赖模型反馈，不是一个可抄到 default_joint_pos 的静态角度数组。
把某一帧实际姿态写成默认值还会改变 action offset、观测零点和几何标定，不能
当作已经修好击球任务。当前脚本不改默认角度，也不自动开启完整训练。

若组合可站稳但不能有效击中：新增独立击球任务，先训练右臂近身定点击球，
保持站立模型的20通道反馈并冻结其权重；右臂策略使用球/身体状态，增加经坐标
验证的拍心、拍面、时机目标及目标变化/速度约束，修正原EE15cm奖励平台。
这属于新训练，不是重复原10000轮。先短训验收实际接触与支撑，再逐步增加发球
分布、身体跟随和整机联合微调。不能把新任务495维观测直接当作站立观测加载。

若右臂输出使整机失稳：先收紧上肢动作范围/变化速度，训练考虑稳定性的击球动作；
必要时以站立模型为教师对全身微调。永久锁定右臂不能完成击球，冻结权重也不意味着
冻结腿关节。完整训练不应在现有证据下靠替换默认姿态直接启动。

本地可验证语法、观测代数、通道映射、接触窗口和部署保护；本机没有Isaac/PyTorch，
不能在此验证实际动力学、PhysX过滤视图绑定或两模型组合的技能表现。远程效果以
用户容器输出为准。原任务、资产、旧模型、保护清单和兼容补丁均保留。
